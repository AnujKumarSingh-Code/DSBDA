# 1. Import required libraries
import pandas as pd
import numpy as np

# 2. Load the dataset
#    Source: Kaggle Titanic competition – https://www.kaggle.com/c/titanic/data
df = pd.read_csv('train.csv')

# Quick description of the data:
#   - PassengerId: unique ID
#   - Survived: survival (0 = No; 1 = Yes)
#   - Pclass: ticket class (1 = 1st; 2 = 2nd; 3 = 3rd)
#   - Name, Sex, Age, SibSp, Parch, Ticket, Fare, Cabin, Embarked

# 3. Initial inspection
print("First 5 rows:\n", df.head(), "\n")
print("Shape:", df.shape, "\n")              # dimensions
print("Info:\n")
df.info()                                    # data types & non-null counts
print("\nMissing values per column:\n", df.isnull().sum())

# 4. Summary statistics
print("\nDescribe numeric vars:\n", df.describe())
print("\nDescribe object vars:\n", df.describe(include=['object']))

# 5. Data types and conversions
#    Let’s convert:
#      - 'Pclass' → categorical
#      - 'Survived' → boolean
#      - fill missing 'Age' with median
df['Pclass']  = df['Pclass'].astype('category')
df['Survived']= df['Survived'].astype(bool)
df['Age'].fillna(df['Age'].median(), inplace=True)

# Re-check types
print("\nAfter conversions:")
print(df.dtypes)

# 6. Encoding categorical variables
#    Turn 'Sex' and 'Embarked' into numeric dummy columns
df = pd.get_dummies(df, columns=['Sex','Embarked'], drop_first=True)

print("\nColumns after get_dummies:\n", df.columns.tolist())

# Now `df` is ready for downstream modeling or analysis!

Here’s a self‐contained example you can drop into a Jupyter notebook or .py file. It uses the well‐known Titanic dataset from Kaggle (you can download it from https://www.kaggle.com/c/titanic/data – “train.csv” and “test.csv”). Just place the CSV in your working directory (or adjust the path).

```python
# 1. Import required libraries
import pandas as pd
import numpy as np

# 2. Load the dataset

df = pd.read_csv('train.csv')

# Quick description of the data:

#   - Survived: survival (0 = No; 1 = Yes)
#   - Pclass: ticket class (1 = 1st; 2 = 2nd; 3 = 3rd)

# 3. Initial inspection
print("First 5 rows:\n", df.head(), "\n")
print("Shape:", df.shape, "\n")              # dimensions
print("Info:\n")
df.info()                                    # data types & non-null counts
print("\nMissing values per column:\n", df.isnull().sum())

# 4. Summary statistics
print("\nDescribe numeric vars:\n", df.describe())
print("\nDescribe object vars:\n", df.describe(include=['object']))

# 5. Data types and conversions
#    Let’s convert:
#      - 'Pclass' → categorical
#      - 'Survived' → boolean

df['Pclass']  = df['Pclass'].astype('category')

```

**What each block does:**
1. **Imports** `pandas` and `numpy`.  
2. **Loads** “train.csv” from Kaggle’s Titanic dataset and briefly describes its fields.  
3. **Inspects** the first rows, overall shape, detailed info (including non‐null counts), and missing‐value counts.  
4. **Summarizes** numeric and object (string) columns.  
5. **Converts** data types to more appropriate ones and imputes a missing‐value strategy for `Age`.  
6. **Encodes** the `Sex` and `Embarked` categorical variables into numeric dummy variables (dropping one to avoid collinearity).

You can adapt the file path or dataset as needed—just point `pd.read_csv()` at your uploaded file.



That single line does three things under the hood:

1. **Interprets the numeric values as categories**  
   While your CSV has 1, 2, and 3 stored as integers, pandas will now treat them as discrete labels (levels) rather than as numbers you’d do math on.  

2. **Uses a more compact in-memory representation**  
   Internally, pandas will keep a list of the distinct categories (`[1, 2, 3]`) and store each row as a small integer “code” referring back to that list. That can save memory compared to holding full 64-bit integers if your dataset is large.

3. **Enables category-specific operations**  
   Once a column is categorical, you can easily ask for its levels, reorder them, group by them, or even set an explicit ordering (e.g. “3rd class < 2nd class < 1st class”). It also prevents you from accidentally performing nonsensical arithmetic on something that really just labels groups.

So by doing:

```python
df['Pclass'] = df['Pclass'].astype('category')
```

you’re telling pandas “this column represents a finite set of buckets, not a continuous numeric quantity”—which both enforces the right semantics in downstream analysis and often improves performance.


Here’s a deeper dive into exactly what happens when you run:

```python
df = pd.get_dummies(
    df,
    columns=['Sex', 'Embarked'],
    drop_first=True
)
```

---

### 1. Why “one-hot” (dummy) encoding?  
Most machine-learning algorithms and statistical models require numeric inputs. Categorical labels like “male” / “female” or “S” / “C” / “Q” must be converted into numbers—but simply assigning 0, 1, 2 can accidentally introduce an ordering (e.g. “C” < “Q” < “S”). One-hot encoding avoids that by:

- Creating a separate binary column for each category.
- Indicating presence (1) or absence (0) of the category.

---

### 2. `pd.get_dummies` parameters

| Parameter        | What it does                                                                                         |
|------------------|------------------------------------------------------------------------------------------------------|
| **`df`**         | Your original DataFrame.                                                                             |
| **`columns`**    | A list of the column names you want to transform (here, `['Sex', 'Embarked']`).                      |
| **`drop_first`** | If `True`, pandas will drop the first category of *each* column, leaving _k – 1_ dummy columns instead of k. |

---

### 3. Step-by-step

1. **Scan the `Sex` column**  
   Unique values: `['male', 'female']`.  
   • With `drop_first=True`, pandas will create only one new column—`Sex_male`.  
     - Rows where `Sex == 'male'` → `Sex_male = 1`  
     - Rows where `Sex == 'female'` → `Sex_male = 0`  
   The dropped first category (`female`) implicitly becomes the baseline: whenever `Sex_male == 0`, you know `Sex` was “female.”

2. **Scan the `Embarked` column**  
   Unique values: `['S', 'C', 'Q']`.  
   • With `drop_first=True`, pandas will create two columns—`Embarked_C` and `Embarked_Q`.  
     - `Embarked_C = 1` if the passenger embarked at Cherbourg, else 0.  
     - `Embarked_Q = 1` if at Queenstown, else 0.  
   The dropped category (`S`, Southampton) is the baseline: when both `Embarked_C` and `Embarked_Q` are 0, it means `Embarked == 'S'`.

3. **Remove the original columns**  
   `get_dummies` automatically drops the original `Sex` and `Embarked` columns, replacing them with your new dummy columns.

4. **Return a new DataFrame**  
   Because we assign it back (`df = …`), your variable `df` is now the transformed DataFrame, ready for numeric-only algorithms.

---

### 4. Why `drop_first=True` (avoid the “dummy-variable trap”)?

If you include _all_ k dummy columns for a k-category variable, they sum to 1 for every row (e.g. if Sex_male=0 and Sex_female=0 can’t happen, but if you had both Sex_male and Sex_female as separate columns they’d be perfectly collinear). In linear models this perfect multicollinearity makes the matrix of inputs singular (non-invertible). Dropping one category:

- Keeps full information (you can always reconstruct the dropped level).
- Prevents that collinearity.
- Simplifies interpretation (the intercept implicitly corresponds to the dropped baseline).

---

### 5. Final result

After running:

```python
df.columns
```

you’ll see something like:

```
[
  'PassengerId', 'Survived', 'Pclass', 'Name', 'Age', …,
  'Fare', 'Cabin',
  'Sex_male',         # 1 = male; 0 = female
  'Embarked_C',       # 1 = Cherbourg; 0 = otherwise
  'Embarked_Q'        # 1 = Queenstown; 0 = otherwise
]
```

Now every column in `df` is numeric, with no hidden ordering, and no redundant dummy column—perfect for feeding into scikit-learn, statsmodels, or any ML pipeline.
